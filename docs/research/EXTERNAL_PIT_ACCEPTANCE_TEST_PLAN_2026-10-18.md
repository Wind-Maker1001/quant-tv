# 外部历史PIT最小样本验收测试方案 v1

日期：2026-10-18。项目：`Wind-Maker1001/quant-tv`。**NO LIVE MONEY**。

配套[字段与验收规范](EXTERNAL_PIT_ACCEPTANCE_SPEC_2026-10-18.md)。这是未来取得材料后执行的测试设计，**不是已完成的外部数据验收，也不含成员数据夹具**。本轮没有运行下表的真实样本或负例测试。所有未来用例初始为NOT_RUN；当前证据支持的陈述只按原报告引用。

## 1. 最小输入包与停止顺序

| 包 | 最小输入范围 | 当前准备情况 |
| --- | --- | --- |
| S0 来源包 | 一套实际交付的原字节/采集收据、原生字段字典、请求/分页（若适用）、授权范围和历史版本/修订链 | 尚无待接入Wind或新官方基线包；接口及原生字段名UNKNOWN |
| S1 起点 | 2021-09-13目标时段完整500名单；起点过渡、独立日历、500条历史身份与知识时间证据 | 权威完整基线未取得，成员数量UNKNOWN；不能运行真实正例 |
| S2 13888 | 同一实际边界前后各一份完整原生快照、实施确认/修订链、现有公告及100个候选动作、历史身份/版本证据 | 当前动作50/50、备选25可定位；独立B0/B1、实际日和历史版本仍缺 |
| S3 换码 | 2025-02-14、02-17、02-18候选时段各一条历史主表记录及2021-09-13一条供应商别名记录；对应日历和时间证据 | 仅有变更来源陈述与事后齐证；完整IdentitySnapshot仍不合格 |

上述是最小**证券与成员证据**，不需要6,411万行行情。S0先验字节、语义和历史版本；不能通过则隔离留存，停止该包的规范投影。S1—S3可以分别整理，但任一小样缺失不得给出全期合格结论。S2前后完整名单必须真实取得，不能为节省材料而用本地动作生成一份替代。

## 2. 逐步验收清单

1. 给交付分配新package_id，原件排他写入；采集时间、原件SHA/字节数、URL或供应商导出定位分别记录。原件下载失败不生成空表。
2. 复核S0原生字典和日期/版本/状态定义。逐个原生字段映射到规范字段，保留原字段和值。API返回总数、页数和实际行数对账；静态文档核对全部页/工作表/目标区块。保留供应商错误码与更正。
3. 原件中每个必需事实绑定行/单元格/页码、版本和置信度维度。先检查UNKNOWN、冲突及NOT_APPLICABLE理由，再检查格式。日期语义不明确时不得靠格式正确放行。
4. 执行规范B01—B08：S1目标指数/日期/时段、完整500、历史身份、状态及起点特殊边界逐项对账。每一步输出失败原始行定位，保留原始计数，禁止自动修复。
5. S2先认证实际边界、历史版本与事件隔离，再执行第3节集合差；每项保存真实两边差集和原件引用。没有B0/B1只报告NOT_RUN。
6. S3先执行第4节身份用例；旧/新代码均保留原生记录，检查稳定身份和知识时间；不据点样本外推连续区间。
7. 仅已获证的内容才允许进入独立隔离投影候选。复用严格date-only、日历、每日500、身份及来源工件校验；保留原件→投影的字段转换日志。该步骤不调用发布型`import-universe`、DatasetBuilder或正式数据根。
8. 运行第5节拒绝案例，逐项断言“拒绝并保留原件，无正式导入/写PASS/状态变更”。实现缺失的检查保持NOT_RUN，不能勾选通过。
9. 审查范围明确写出证据包、版本、日期、时段、输入哈希、检查器版本、用例实际执行状态及阻塞。小样本证据通过后，SOURCE_BINDING与其他Formal/Forward门禁仍按现有代码拒绝。

## 3. 13888可执行化测试设计

符号定义沿用主规范。集合元素使用经证实的稳定身份，另保存每份快照的当时symbol，不能只对比字符串。计划日期不是实际边界输入。

| ID | 输入及检查 | 预期结果/失败条件 |
| --- | --- | --- |
| E01 | 正文、附件原件/浏览器表示、采集收据与父引用逐层比SHA；核对000905区块及原生行坐标 | 原始XLSX与派生表可重放；容器/文本不能冒充原响应 |
| E02 | 重放既有公告解析与13888分块工作表比较，逐个核对动作/代码/名称；备选单列 | 目前候选ADD=50、REMOVE=50、RESERVE=25，A/R无重复且不相交；不认证实际发生 |
| E03 | 取得实施确认及更正/撤销/改期链，证明实际边界与时段；核对同版本known_at | 任一未知拒绝后续真实差集用例；不能自动使用2021-12-10或12-13 |
| E04 | B0/B1都来自已定位原生完整快照，日期/时段分别处于已证实边界两侧 | 各500个唯一历史代码和稳定身份；不是同一表套用动作后再导出；同源官方两快照可用，但须各有原件 |
| E05 | 对比原生交易所代码及稳定身份；检查边界间其他事件目录/更正和代码变更 | 无其他未经解释变化；事件隔离无法证明则拒绝本案例 |
| E06 | 核对`R⊆B0`、`A∩B0=∅`及A/R均50且不交 | 原件动作必须与边界前成员相容；不能只数动作 |
| E07 | 实际计算`B0\B1`和`B1\B0`，分别与R/A逐元素相等 | 真实差集各50、共同450、B1等于替换结果；输出所有多余/遗漏项而非截断摘要 |
| E08 | 检查B0/B1版本在对应signal_as_of可得；盘中与收盘后按有证据语义投影 | 事后正确表与历史PIT输入分开；只有计划或回溯最新版拒绝 |
| E09 | 留存E01—E08输入/实现哈希、结果及范围，独立审查重放 | 即使全部通过，也只认证此边界；不推定另外13条或五年完整性 |

E06—E07的正例预期是集合代数，**不包含本轮生成的500只股票**。后续夹具可使用显著标记的抽象集合验证算法，但真实500要求不改变；软件夹具通过不等于E04已取得真实快照，更不能标真实数据合格。

13888实际场景的当前状态：E01/E02已有第一阶段复核证据可引用，不能重复称新数据认证；E03—E09真实证据验收未执行。正文日期2021-11-26、计划2021-12-10收盘后、附件createAt=2021-11-30的时间冲突必须出现在验收收据中。

## 4. 历史身份最小样本与断言

| ID | 检查设计 | 正例所需证明/当前缺口 |
| --- | --- | --- |
| I01 | 2025-02-14候选记录：原生code、交易所、稳定ID、A_SHARE、listing_date、有效时段和available_at | 只能依据该时段主表验300114；不能凭变更公告或交易日历生成旧区间末日 |
| I02 | 2025-02-17候选开市记录与实际启用证据 | 当时302132、生效时段及同一证券关系；现有双材料齐证不补全主表/known_at |
| I03 | 2025-02-18候选记录：新代码有效、旧代码无冲突、稳定ID保持 | 独立日历和该时段主表；三个点不能证明中间所有历史与全部生命周期 |
| I04 | 一条早期供应商记录仍为原生302132；供应商namespace/ID/历史别名语义映射到证实的当日代码 | 不把供应商回溯标签当交易所代码，不重写任何价格行；缺别名或身份合同拒绝 |
| I05 | 使用既有`IdentitySnapshot.validate/resolve`的未来小夹具，按原字段构造有证据闭区间 | 每个date/symbol恰一身份；同symbol或security_id区间不重叠；身份源SHA属于工件集合；available_at≤signal_as_of |
| I06 | 区分别名边与IdentitySnapshot区间；源原件、已证实区间和知识时间全部可重放 | 未知listing/start/end/available_at保持UNKNOWN，不调用正式投影；当前本地候选ID不冒充外部主键 |

身份的原始证券ID、经证实的本地stable ID与交易所代码应分别有命名空间。ID一致不证明CSI500成员；PIT成员还须独立原件。重组/重新上市关系不属于SAME_SECURITY时，沿用现有拒绝行为，另需独立合同；不为本样本放宽。

## 6. 未来验收收据与复现要求

每个用例保存：case_id、预期结果、实际PASS/FAIL/NOT_RUN、输入包和原件SHA列表、事实/原生行定位、实现SHA、执行时刻、实际结果/差集路径、拒绝原因、证据覆盖范围。若依赖项失败而未运行，状态必须NOT_RUN并指明阻塞用例；UNKNOWN不记PASS。

收据还须记录正式数据发布/正式资格/训练/回测/Forward动作均未发生，以及旧文件哈希检查结果。失败用例的“PASS”只代表**拒绝行为符合预期**，不代表失败数据合格；真实正例的数据资格和负例软件行为必须分别记录。
