# quant-tv 平台边界与受控实盘迁移路线

2026-10-13（Asia/Shanghai），PR #1 合并前架构保护。当前阶段：Python 3.9，**NO LIVE MONEY**。

quant-tv 的长期目标是 **研究 → 回测 → 模拟盘 → 受控实盘**。FactorLab 是研究核心，
不是整个项目的终点。本次修复数据准入与研究窗口、保留业务资产并定义后续验收条件；
没有实现交易网关，也没有提前重构 Legacy 系统。

## 模块责任与依赖方向

| 边界 | 职责 | 输出与授权限制 |
| --- | --- | --- |
| 数据资格服务 | 原文归档、固定解析合同、PIT/身份/单位/状态/公司行为、历史可知审查 | 发布可核验数据版本；软件 PASS 不授予金融认证 |
| FactorLab 研究 | 冻结配置、14 因子、四模型、验证、报告、研究证据与 Paper 信号 | 预测/目标权重及数据、模型、时间身份；不得导入交易 SDK、读取交易秘密或发真实资金订单 |
| 回测 | 在明确价格、成本、T+1、整手与公司行为账本假设下评价目标 | 模拟订单/成交/净值；离线执行回测不是经纪成交回报 |
| 模拟盘服务（未来独立） | 消费经授权信号，运行仿真账户、订单状态机、回报与对账 | 使用模拟网关，与真实账户隔离；Paper Forward 记录不等于完整模拟盘 |
| 执行与风控服务（未来独立） | 部署授权、信号验真、预交易风控、持久化订单、网关、回报、账本与对账 | 唯一可拥有经批准真实账户权限的模块；研究成功本身没有下单权限 |
| GUI / 运维控制面 | 状态展示、授权/撤销部署、Kill Switch、恢复审批 | 使用受控 API，不在界面导入研究模块后直接调用券商 |
| 发布与调度 | 分组件构建、测试、制品身份、环境部署与人工放行 | 构建不登录账户；发布成功不自动批准交易 |

这是责任设计，不是本轮新增的目录或服务。保持 `qbot.research` 隔离入口，未来通过
版本化信号契约交接；执行服务独立验证，研究 notebook、CLI 和训练程序都不能成为
实际订单发送者。`live_trading=false` 是研究配置守卫，不是独立 Legacy 的全仓库断电开关。

## 暂停旧工作流的原因与安全替代

旧 auto-trade 用 cron 直接执行 Legacy 策略/GUI 和通知，缺少当前仓库有效授权与
输入，也没有独立预交易风控、幂等委托、对账与恢复验收。不能为了恢复长期方向而
重新启用。旧 release 是上游多项目模板，存在退役 Runner/Action、无效任务依赖和
缺失制品输入；应保留业务资产，替换发布协议。详情见
[CI_STANDARDIZATION.md](../ci/CI_STANDARDIZATION.md)。

替代路线：隔离 Legacy 构建与只读兼容测试 → 模拟网关独立手动验收 → 确认组件、
目标环境、固定依赖、有效制品与最小发布权限 → 建立受控发布。交易调度只能唤醒
已有有效授权的执行服务，不能运行研究入口直接下单。真实部署另需人工批准和环境
门禁，不由 PR、标签或发布事件自动开启。

## 阶段迁移与进入条件

1. **当前研究阶段。** 保留 FactorLab、Legacy 和历史收据；Forward 与研究实盘入口
   关闭。正式五年研究仍需真实 PIT、状态及全链来源证据，合成测试不替代。
2. **数据资格与回测阶段。** 按来源完成解析绑定和独立历史可知审查，保持 500 成员
   与冻结窗口；另行完善公司行为权益/现金账本。以冻结版本复现四模型与回测，
   记录模型边界，再决定是否进入模拟盘。
3. **独立模拟盘阶段。** 定义信号到目标仓位/订单意图的协议；建立模拟网关、持久化
   状态机、回报、账本、对账和控制面。在无真实凭据环境验证下面全部故障场景。
4. **受控实盘阶段。** 用户明确批准策略、账户、标的、资金/风险额度、有效期与撤销
   权限。在隔离服务中配置秘密，先完成沙箱/只读对账验收；全部条件通过后才可
   限额灰度。扩资或增加账户须重新授权，不能沿用旧 cron 的隐式交易许可。

## 实盘启用前必须取得的验收证据

| 条件 | 要求与必须验证的失败场景 |
| --- | --- |
| 独立授权 | 绑定账户、策略/代码/模型版本、资金及风险限额、标的白名单、时段与到期时间，独立于研究收据。缺失、过期、撤销或身份不符均拒单；撤销重启后仍生效 |
| 预交易风控 | 发送前以新鲜行情和已对账账户核对资金、可卖持仓、重复/未决委托、整手/T+1、停牌/涨跌停、价格偏离、敞口、集中度、日损失和速率。陈旧数据、风控不可用或未知规则均拒单，策略不能跳过 |
| 幂等订单 | 唯一意图/客户订单 ID 绑定策略运行与交易日，持久化后发送，保存经纪 ID 映射。并发重复、超时、发送后崩溃与重连均不能重复下单；结果不明先查询/对账，禁止盲目重发 |
| 成交回报 | 幂等保存接受、拒绝、部分/全部成交、撤单和撤单竞争的原始事件及应用结果。乱序、重复、丢失、迟到回报不能重复计现金/仓位；委托确认不是成交 |
| 账户对账 | 启动前、定期、日终和异常后核对经纪现金/可用/冻结金额、持仓/可卖数量、未决订单、成交、费用与权益。未解释差异阻止新增订单，不能凭推测自动修正账本 |
| Kill Switch | 独立于策略进程，可全局/按账户/按策略阻止新增委托；受控撤单并核实。经纪不可用时显示撤单未确认，不能声称已平仓；状态持久化，恢复须明确批准 |
| 故障恢复 | 持久化日志、订单/回报检查点、单写者租约与 fencing 防双实例。断网、经纪重启、进程崩溃、磁盘满、时钟偏移和控制面失联进入保护态；先对账并解释未决订单，再人工恢复，不能启动即重发信号 |
| 隔离与发布 | 研究/回测 CI 不持有交易秘密，账户凭据仅执行服务可用，日志脱敏。制品身份可核验，代码可回滚；不能回滚已发生订单和资金账本。部署、授权、启用与扩资分别审计 |

这是后续实现的阻塞验收条件，当前代码未被认定已经满足。未来须提供模拟故障测试
和可审阅运行证据。本轮没有恢复工作流、创建网关、写入秘密、激活 Forward 或真实下单。
